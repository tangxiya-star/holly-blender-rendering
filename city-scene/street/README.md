# Copenhagen street environment

Open **`copenhagen_neighborhood.blend`** in Blender 5.2 or newer for the latest **four connected streets** scene. It contains 104 generated buildings, 13 cameras, and a closed walking route of approximately 269 m. This is an editable representative Copenhagen neighborhood with a fictional street plan and reference-based architecture. It is separate from the [city aerial scene](../aerial/README.md) and the Alchemist interior project.

## Restore the assets

From the repository root, run:

```sh
python3 tools/restore_assets.py --archives city-street-assets.zip
```

The script downloads and verifies the street asset archive from [Release v2026.09.08-projects](https://github.com/tangxiya-star/holly-blender-rendering/releases/tag/v2026.09.08-projects), then restores the Blender scenes, renders, textures, and photographic references under `city-scene/street/`. Python 3 and GitHub CLI (`gh`) are required for the download command. The source checkout alone does not contain these large files. See the [repository README](../../README.md) for the full restore instructions.

The latest review images are `renders/neighborhood_overview.png`, `renders/neighborhood_north_street.png`, `renders/neighborhood_east_street.png`, `renders/neighborhood_south_street.png`, and `renders/neighborhood_turn.png`.

## Explore the latest scene

The file opens at camera **08 · FOUR STREETS - overview**. Choose a camera under Scene Properties → Camera, then use Numpad 0 to view it:

| Camera | Purpose |
|---|---|
| 01 · Human eye street | Original main-street view, 1.7 m above the footway, 32 mm |
| 08 · FOUR STREETS - overview | North-up overview of the connected street perimeter |
| 09 · North street - eastbound | Human-eye view along the north street |
| 10 · East street - southbound | Human-eye view along the added east street |
| 11 · South street - westbound | Human-eye view along the south street |
| 12 · TURN HERE - north intersection | View into the north intersection |
| 13 · FULL LOOP - all four streets | Animated walking route through the complete perimeter |

For the complete walking preview, select camera **13**, return to frame 1, and play the timeline. The route uses 24 fps and a modeled walking speed of 1.4 m/s. [Neighborhood navigation data](reports/neighborhood_navigation.json) records the route, timing, and intersection locations. [Neighborhood validation](reports/neighborhood_validation.json) reports a closed loop, clear sampled walking surfaces, no sampled building collisions, and no missing images in the saved validation run. This is camera-path validation, not a full physics/collision system.

For free exploration in the 3D View, press **F3**, search **Walk Navigation**, and press Enter. Use **WASD** and mouse look; the wheel changes speed. Click to accept the view or Escape to cancel. This uses Blender's native navigation, not a standalone game controller.

The four-street expansion retains 66 buildings from the earlier scene and adds 38. Its architecture, surfaces, and route are generated by `scripts/neighborhood_architecture.py`, `scripts/neighborhood_surfaces.py`, and `scripts/neighborhood_navigation.py`, assembled by `scripts/expand_neighborhood.py`.

### Earlier scene and scale

Three connected streets: a 190 m main route and two 160 m cross streets with short context extensions. The 18 m main corridor contains a 5.6 m carriageway, two 2.5 m raised cycle tracks, granite curbs, and two 3.4 m sidewalks. Main buildings are narrow 3–5-storey parcels. This earlier stage contains 86 generated buildings, including four additional facades that close side-street sightlines; eight street corners have return facades.

Facade shells contain real openings, recessed casements, interior depth and varied linen curtains. Ground-floor shops have shallow display interiors; these are not fully explorable destination interiors. Roofs, gutters, dormers, crosspost windows, concrete-and-granite footways, suspended lamps, and 26 instanced bicycles establish the local visual language. The bakery, courtyard and gallery have POI markers for a later interior phase.

Architecture and street dimensions are modeling assumptions, not surveyed measurements. See `references/reference_analysis.md` for the distinction and source photographs.

Restore the assets first, then run the following from the repository root with Blender 5.2 or newer available as `blender`. These commands regenerate the scene checkpoints and renders in this folder:

```sh
cd city-scene/street
blender --factory-startup --background --python scripts/01_blockout.py
blender --factory-startup --background copenhagen_01_blockout.blend --python scripts/02_detail.py -- --reviewed
blender --factory-startup --background copenhagen_03_refined.blend --python scripts/03_refine.py
blender --factory-startup --background copenhagen_final.blend --python scripts/validate_scene.py
blender --factory-startup --background copenhagen_final.blend --python scripts/expand_neighborhood.py
blender --factory-startup --background copenhagen_neighborhood.blend --python scripts/validate_neighborhood.py
```

The initial blockout was built and rendered through Blender MCP. The shared MCP scene later changed to a separate food project, so subsequent builds used isolated Blender processes against these saved checkpoints. Existing Alchemist files were not overwritten.

## Materials and sources

Building and paving materials are procedural PBR shaders with meter-scale texture coordinates, fine bump, roughness variation and restrained wear. The road and cycle tracks combine this with packed CC0 **Asphalt 02** color, normal and roughness maps by Rob Tuytel from [Poly Haven](https://polyhaven.com/a/asphalt_02), mapped at the documented 3 m scale. Bicycles reuse collection instances; architecture batches disconnected components by material per building. The packed photographic environment is **Overcast Soil (Pure Sky)** by Sergej Majboroda and Jarod Guest, CC0, from [Poly Haven](https://polyhaven.com/a/overcast_soil_puresky). It supplies sky and illumination only. Reference street photographs were used for analysis and are not mapped onto the buildings. Their original sources and usage notes are preserved in [External asset provenance](references/assets.md) and [Reference analysis](references/reference_analysis.md). The reference images accompany the asset archive for that documented purpose.

Cycles is used for review renders, with denoising and Metal GPU rendering where available. Visual approval is still required before claiming photographic fidelity or beginning web optimization. There is no Three.js export in this phase.
